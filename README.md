# Deep Vein Idle 自给成长与职业助手

[Deep Vein Idle](https://deepveinidle.com/)（含 [中国入口](https://cn.deepveinidle.com/)）的 Tampermonkey 用户脚本。它替你安排练级、供料、装备、强化、买卖、收菜和世界 Boss，默认暂停，点“开始调度”才会动手。

当前版本 **v0.12.3**，由本 fork 维护 · [更新日志](CHANGELOG.md)

## 安装

1. 安装 Tampermonkey。
2. 打开 [安装链接](https://raw.githubusercontent.com/JackyXu866/deepvein-idle-helper/modular-rewrite/deepvein-balanced.user.js) 并确认安装（GitHub 打不开时用 [Gcore CDN 备用链接](https://gcore.jsdelivr.net/gh/JackyXu866/deepvein-idle-helper@v0.12.3/deepvein-balanced-cdn.user.js)）。
3. 刷新游戏，从右侧工具栏打开“脚本助手”，选好策略和战斗职业，点“开始调度”。

只启用一份助手，只开一个游戏标签页。以后有新版时，油猴会按它自己的设置更新；助手标题旁也会提示，点“安装／更新”后刷新游戏才生效。从上游或旧链接装过的，请用上面的链接重装一次，以后才会从本 fork 更新。

## 策略

| 策略 | 做什么 |
| --- | --- |
| 自主发展（默认） | 选一个值得的等级或解锁，备好装备和整批材料后做完，再选下一个；各技能保持在一定等级差内 |
| 经验优先 | 按总经验效率选工作，允许技能差距拉大 |
| 主业经营 | 专做你选的主业（可固定具体工作或怪物），或按收益自动选 |
| 补精通 | 按“每点精通花多少金币”赚精通点数：补收藏下一档，同时在后台强化刷强化记录 |
| 只收菜＋蹭世界 Boss | 只收菜补种、参加 Boss 和做每日／每周任务，做完任务恢复你原来的工作；练级和队列由你自己安排 |

战斗职业（法师、单手／双手战士、短弓／长弓游侠）决定需要战斗时用哪条路线。换策略、主业或职业会暂停调度，游戏里正在做的任务不受影响，点“开始调度”后在任务边界接手。每种策略都会先完成每日任务，再做每周任务（只收菜模式在你的游戏队列有内容时不接手）。

## 它怎么做决定

几条统一的规则，面板上显示的就是它实际在用的数：

- **时间就是钱**：金币按“金币效率”（最赚钱的工作每小时多少金币）折成时间。花钱、花材料、花时间都放在一起比，买和自己做取更省的。
- **回本才做**：任何花费（装备、强化、房屋、增益食物……）省下的时间要至少是花费的 1.2 倍。
- **投资表**（总览）：每个装备位的升级办法都在一张表里比较：换上已有的、市场买、自己做、强化（最高 +20，失败回到 +0 的期望花费已算进去）。只做表上标“值得”且最省的那一项；强化在后台进行，不打断当前任务。
- **精通两页**（在游戏里买了第二页时）：第二页精通只点强化成功率，强化时自动切过去，没有要强化的就切回第一页。投资表按第二页的成功率算强化花费。
- **出售**：按当日成交均价定价，买单接近均价就直接卖，明显低于均价就按均价挂单；同一物品 30 分钟内只卖一批。
- **稀有发现**：掉落和采集品质按游戏的公式算：护身符和工具的幸运，乘上猎人药剂、矿脉祝福、寻宝精通、幸运神龛的加成。猎人药剂和寻宝精通的价值，就是它们每小时多带来的稀有品质能卖多少金币。
- **精通加点**：精通加了不能退，所以每次都按当前目标求整体最优的分配，不是每点各加一级：补精通时只看哪项让接下来的收藏目标最省金币（含存仓走路；经验和战斗项对收藏没用，不会点），主业经营看每小时金币，练级看实际在做的工作省多少时间。面板写出按什么算、加点前后差多少。
- **库存的价值**：助手会卖的东西，用掉按卖价算成本；助手不会卖的（比如关掉“平时也出售多余物品”时），用掉不算花费。

## 设置（策略 / 物资页）

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 按收益采购 | 开 | 买材料、装备、药水，前提是比自己做省 |
| 平时也出售多余物品 | 关 | 关着时，只卖为赚钱而做的工作的产出 |
| 满仓时出售普通盈余 | 开 | 仓库满时清理超出保留量的普通物品 |
| 出售制作产出 | 开 | 卖掉练制作技能做出来的多余成品 |
| 比价自动补药水 | 开 | 药效快用完时补上，按药效和价格比较 |
| 自动升级房屋 | 开 | 扩建地块、给设施投料升级，回本才做 |
| 种植方式 / 收菜时机 | 自动 / 全部田成熟 | 也可以指定作物，或同种田一熟就收 |
| 世界 Boss 参战方式、时段、跳过概率 | 全程打 | 有矿脉祝福且游戏的“自动参加世界首领”开着时，由游戏去打，这几项不生效 |
| 物品目标 | — | 指定一件普通物品和要多做的数量，集中备料做完后回到原策略 |

设置保存在当前浏览器。同一标签页刷新、掉线重连后，正在运行的调度会自动继续。

## 不会动的东西

- 传说物品：不卖、不吃、不当材料、不丢。穿着的传说装备可以按投资表强化，强化失败不会毁掉装备。
- 药水、稀有和特殊掉落、坐骑、宠物、种子、计划要用的材料、在用装备不会被卖掉。
- 你自己的挂单、你在游戏里排的队列、你给每块田选的作物。
- 不花宝石，不捐赠，不替你验证邮箱或设置账号。

## 注意

- 这是有限范围内的估算规划，不保证最优或一定盈利；行情、掉落和服务器状态都会变。
- 账号没有验证过邮箱时，游戏不允许用市场，助手会改为自给和卖给商人。
- 电脑休眠、关掉页面、服务器维护会中断运行。请遵守游戏的自动化规则。
- 两个游戏域名的设置互不相通，换域名后要重新开始一次。

## 开发

源码在 `src/`（ES 模块），用 esbuild 打包；不要直接改根目录的 `*.user.js` / `*.meta.js`。

```
npm install
npm run build
npm test
```

- 代码结构、一次决策怎么走、共享规则在哪个文件：见 [docs/architecture.md](docs/architecture.md)。
- **必须共用模块**：每条规则、每个决定只在一个模块里实现，所有功能都调用它，不另写一份，否则面板显示和实际行为、或两个功能之间就会出现不一致。缺的情况加进共享模块，新的共享规则登记到 architecture.md。
- 发布：`npm version <版本> --no-git-tag-version`，在 [CHANGELOG.md](CHANGELOG.md) 顶部加一节，构建并确认测试全过，提交、打 `v<版本>` 标签，把分支和标签推到 fork。发布地址只在 `scripts/build.mjs` 的 `REPO`、`BRANCH` 设一次。
- 待办见 [docs/roadmap.md](docs/roadmap.md)。
